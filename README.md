# notification-bot

Telegram-бот, который напоминает о подписании табеля учёта рабочего времени
**около 15-го числа и в конце каждого месяца в 11:00 по Москве**, с учётом
выходных и праздников РФ (напоминание переносится на ближайший рабочий день
**до** даты).

## Особенности логики

- **Два напоминания в месяц.** Первое — на 15-е число, второе — на **последний
  рабочий день месяца** (30-е, 31-е или последний день февраля).
- **Перенос.** Если целевая дата выпадает на выходной/праздник — напоминание
  уходит в последний рабочий день перед этой датой. Например, 15-е в субботу →
  напоминание в пятницу 14-го.
- **Конец месяца.** Второе напоминание — это именно последний рабочий день:
  в июле это 31-е (рабочая пятница), в феврале — 28/29 (или ближайший рабочий
  день до), и т.д.
- **Декабрь.** 15-е — обычное напоминание (с переносом). 16-го числа (строго)
  приходит сообщение: *«Подписание финального табеля за декабрь отслеживайте
  самостоятельно на корпоративной почте»*. Второе напоминание (30-е) в декабре
  не отправляется, с 16 по 31 декабря больше ничего не приходит.
- **Календарь.** Производственный календарь РФ на 2026 год встроен в бинарник
  (`internal/calendar/data/2026.json`, формат [xmlcalendar.ru](https://xmlcalendar.ru)).

## Как это работает

Пользователи подписываются командой `/start`. Их `chat_id` сохраняются в
`subscribers.json`. Каждый день в 11:00 (по `TZ`) бот проверяет, нужно ли слать
напоминание, и рассылает его всем подписчикам. Журнал `sent.json` защищает от
повторной отправки при рестарте.

### Команды бота

- `/start` — подписаться на напоминания.
- `/stop` — отписаться.
- `/status` — узнать дату ближайшего напоминания.

## Настройка

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Скопируйте `.env.example` в `.env` и впишите токен:

   ```bash
   cp .env.example .env
   # отредактируйте BOT_TOKEN=...
   ```

### Переменные окружения

| Переменная    | По умолчанию     | Описание                                   |
|---------------|------------------|--------------------------------------------|
| `BOT_TOKEN`   | —                | Токен бота (обязательно)                   |
| `TZ`          | `Europe/Moscow`  | Часовой пояс для расчёта времени           |
| `REMIND_HOUR` | `11`             | Час отправки напоминаний (0–23)            |
| `STATE_DIR`   | `data`           | Каталог для файлов состояния               |
| `TEST_DATE`   | —                | Тестовая дата `ГГГГ-ММ-ДД` (см. ниже)      |

## Запуск

### Docker (рекомендуется)

```bash
docker compose up -d --build
docker compose logs -f
```

Состояние сохраняется в томе `bot-data` (`/data` внутри контейнера).

### Локально

```bash
export BOT_TOKEN=123456:ABC...
go run ./cmd/bot
```

## Тесты

```bash
go test ./...
```

Ключевые тесты — в `internal/schedule` (логика переносов и декабря) и
`internal/calendar` (разбор производственного календаря).

## Проверка отправки (тестовая дата)

Чтобы не ждать реальную дату, задайте `TEST_DATE`. При старте бот один раз
проверит этот день и, если для него предусмотрено напоминание, немедленно
разошлёт его всем подписчикам (в обход журнала отправок — можно повторять).

```bash
# Сначала подпишитесь в Telegram командой /start, затем:
TEST_DATE=2026-12-16 go run ./cmd/bot   # спец-текст про финальный табель
TEST_DATE=2026-02-13 go run ./cmd/bot   # перенос: 15 фев (вс) → 13 фев (пт)
TEST_DATE=2026-01-15 go run ./cmd/bot   # обычное напоминание
```

Если на указанную дату напоминание не предусмотрено — в логах будет строка
`на дату … напоминание не предусмотрено`. Команда `/test` в чате присылает
пример напоминания без привязки к дате.

## Обновление календаря на новый год

1. Скачайте JSON нужного года с xmlcalendar.ru, например:
   `https://xmlcalendar.ru/data/ru/2027/calendar.json`
2. Сохраните его как `internal/calendar/data/2027.json`.
3. Пересоберите бота. Файл подхватится автоматически (`go:embed data/*.json`);
   для года без данных бот использует упрощённое правило «рабочие дни Пн–Пт».
